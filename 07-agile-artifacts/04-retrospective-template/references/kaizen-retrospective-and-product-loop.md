# Kaizen Retrospective and Product Loop

Add these fields to a retrospective or product review:

| Field | Required content |
|---|---|
| Observed gap | concrete event, evidence, and affected output |
| Root cause | process, requirement, design, tooling, skill, or coordination cause |
| Hypothesis | small change expected to improve the gap |
| Measure | leading result, guardrail, owner, and timebox |
| Experiment | reversible action and stop condition |
| Result | evidence, uncertainty, and reviewer |
| Standardisation | skill, template, test, route, or runbook updated |
| Next cycle | remaining problem and re-audit date |

Do not treat a retrospective action as closed until the relevant project gate and evidence chain pass again.
