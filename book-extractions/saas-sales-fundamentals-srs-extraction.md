# The SaaS Sales Method Fundamentals — SRS-Engine Extraction

**Source:** Jacco van der Kooij & Winning by Design, *The SaaS Sales Method Fundamentals.*

**Lens:** What discovery, qualification, and customer-conversation artefacts does the engine need to produce so the team selling and onboarding a SaaS has SDLC-quality documentation?

## One-line takeaway

SaaS sales is operationalised as a **structured discovery framework (Situation–Pain–Impact + TALKER), a 3rd-party-insight library, and a value-quantification workflow (Cost / Experience / Revenue impact)** — every one of these is a *document* the engine should output as part of the sales-enablement and onboarding doc pack.

## Distinctive documentation surface

### 1. Discovery framework spec (SPI)

The book's spine is **S** ituation, **P** ain, **I** mpact questions, with the TALKER conversation framework. The engine should produce a **Discovery Framework Specification** for each product — situational questions library, pain questions library, impact questions library, third-party-reference library, and the call-script using them.

### 2. Customer-centric communication doc

TALKER: Tone, Ask, Listen, Keep notes, Elaborate, Repeat. A **Communication Playbook** with do/don't examples and call-script openings.

### 3. Impact / value-quantification doc

Cost-Experience-Revenue impact framework: Reduce/Improve/Increase across these three axes. The engine should produce a **Value Quantification Worksheet** that every sales conversation populates and every CS plan reuses.

### 4. Email/outreach prep checklist

Industry-specific, company-specific, problem-specific, person-specific. The engine should produce an **Outreach Prep Checklist** template.

### 5. Note-taking & call-recap doc

Standardised symbols ((S)/(P)/priorities/arrows), tone-word capture, recap email template.

## Documentation patterns

- Structured frameworks beat improvisation — every conversation has a *document* it draws from.
- Customer language is captured verbatim; the doc preserves tone-words.
- Third-party references are *libraried*, not invented in the moment.

## Implications for the SDLC-Docs-Engine

1. Add Phase 08 skill **`06-saas-discovery-framework-spec`** producing per-product SPI question libraries + TALKER call script.
2. Add Phase 08 template **`saas-value-quantification-worksheet.md`** (Cost/Experience/Revenue impact).
3. Feed the **Sales Enablement Doc Pack** with these as required components.
