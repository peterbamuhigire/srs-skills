# AI Incident Evidence Pack Spec Template

## 1. Evidence items

| # | Item | Source system | Capture method | Default retention | Access role |
|---|------|---------------|----------------|--------------------|--------------|
| 1 | Trace bundle (per affected request) | observability / tracing system (`{system}`) | automatic on incident declaration; time-bounded export | per severity (sec. 3) | AI lead, SRE, DPO |
| 2 | Prompt + model + tool versions at T | prompt registry; gateway routing config; agent tool registry | scheduled snapshot every N minutes + ad-hoc on declaration | per severity | AI lead, SRE |
| 3 | Retrieval set (per affected request) | vector store / search index (`{system}`) | trace-bundle attachment | per severity | AI lead, SRE |
| 4 | Eval output at T | eval harness store | snapshot the gating run and the calibration-set scores | per severity | AI lead |
| 5 | Customer-affected list | gateway logs + tenant-id lookup | computed at declaration; refined during investigation | per severity; tenant-isolated | AI lead, CSM, DPO |
| 6 | Action audit log (agent-action incidents) | agent tool registry; downstream system audit logs | append-only; immutable | per severity | AI lead, security, DPO, legal |
| 7 | Reproduce script | generated by evidence-bundle exporter (software-dev pass) | one per identified failing prompt + retrieval | per severity | AI lead, SRE |
| 8 | Model-price-table snapshot | provider price catalogue | scheduled daily; snapshotted on cost-runaway declarations | 3 y minimum | FinOps, AI lead |
| 9 | Containment-action log | feature-flag system; gateway; prompt registry; index store; tool registry | append-only audit logs from each system | per severity | AI lead, SRE, IC |
| 10 | Customer comms artefacts | comms system; status-page system; email gateway | exported per send | per severity; redacted per recipient | comms lead, CSM, DPO |

## 2. Chain-of-custody

- Each item is captured to immutable storage (WORM or content-addressed).
- Capture event records: source system, time window, capture operator (or job id), SHA-256 hash, storage URI.
- Modifying a captured item is impossible by design; corrections create a derived artefact with a back-link.
- All captures are listed in the per-incident `manifest.json` produced by the evidence-bundle exporter.

## 3. Retention by severity

| Severity | Retention |
|----------|-----------|
| SEV1 | 7 years |
| SEV2 | 3 years |
| SEV3 | 1 year |
| SEV4 | 90 days |

Override per tenant DPA where longer is contractually required. Honour GDPR Art. 17(3)(b) / 17(3)(e) exceptions; retention does not yield to RTBF if the evidence is required for legal claim or compliance reporting.

## 4. Redaction policy

| Scope | Default | Override |
|-------|---------|----------|
| Other tenants' data | redact | not overridable |
| User-PII fields | redact | regulator may require unredacted under court order |
| Provider-confidential (model architecture under NDA) | redact | only with provider authorisation |
| Internal pricing | redact for customer view | exec sign-off for unredacted |

Each redaction step appended to the manifest with: redaction rule id, operator, time, fields touched.

## 5. Regulator-handover packaging

- Bundle: signed zip; manifest at root.
- Manifest fields: incident id, severity, dates, regulator, limb cited, list of artefacts (filename, hash, source system, capture window), list of redactions, DPO sign-off (name, role, date), legal sign-off.
- Bundle hash recorded in the incident timeline and in the regulator-notification record.
- Cross-link: `09-governance-compliance/18-ai-regulator-incident-notification-doc`.

## 6. Access policy

| Role | Normal-operations access | Customer-distribution view | Regulator-handover view |
|------|--------------------------|----------------------------|---------------------------|
| AI lead | full | n/a (consumer) | requests via DPO |
| SRE on-call | full | n/a | n/a |
| Security on-call | full | n/a | requests via DPO |
| DPO | full | full | originator |
| Legal | full | full | originator |
| Exec sponsor | full | full | informed |
| CSM | redacted to their tenant | tenant-specific | n/a |
| Customer (affected tenant) | n/a | tenant-specific only | n/a |
| Regulator | n/a | n/a | scoped, time-bound, logged |

## 7. Capture tooling (software-dev engine handoff)

The following code is owned by the parallel software-dev engine pass:

- evidence-bundle exporter (turns the items above into a sealed manifest);
- reproduce-script generator (deterministic re-run against pinned configuration);
- price-table snapshotter (provider price catalogue capture);
- containment-action log normaliser (combines flag-system, gateway, prompt-registry, index, and tool-registry audit logs);
- redaction engine (applies the redaction policy from sec. 4 with audit).

This spec defines the contract; the software-dev pass owns the implementation.
